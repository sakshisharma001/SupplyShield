About SupplyShield

SupplyShield is an autonomous software supply-chain security audit and detonation platform developed to defend against dependency confusion, malicious typosquats, and multi-stage backdoors before installation.

Security Jargon Glossary

Architecture Overview

Combines compiler-level AST static inspection, CPython PEP 578 runtime audit hooks, ephemeral Docker containers, and composite risk scoring with SLSA provenance tiers.

Documented Architectural Limitations
  • Weak Sandbox Fallback: In environments without Docker, host subprocess mode cannot isolate native C extensions or direct syscalls.
  • Busy-Wait Logic Bombs: CPU-bound spinloops (while time.time() < t) cannot be fast-forwarded and hit the 10-second watchdog SIGKILL.
  • Compression Utilities: Legitimate packages using gzip.decompress() trigger baseline suspicion (Score: 40) to prevent unpacking blindspots.

What is SupplyShield?

The Problem: Software Supply-Chain Attacks

When developers run pip install library-name, Python can run arbitrary code immediately during installation. Malicious actors publish typosquatted packages or backdoor existing libraries to steal AWS keys, deploy ransomware, or install reverse shells.

How SupplyShield Protects You

  1. Compiler AST Analysis: Checks the code structure for hidden commands, Base64 unpacking, and Trojan Source character tricks.
  2. Isolated Room (Sandbox): Runs the code in an isolated environment with synthetic decoy keys and PEP 578 audit hooks to see if it tries to steal credentials or reach the internet.
  3. Composite Verdict: Combines findings into an actionable verdict: "Looks safe" or "Dangerous: do not install".
